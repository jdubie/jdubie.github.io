# Make a YAM arm follow trajectories as closely as you can

There is a YAM 6-DOF arm (gripper fixed shut). It is the same arm as in `tools/yam_nominal.xml`, but that file is
only nominal: the real arm's link masses, centres of mass, inertias, link lengths, rotor inertias, joint friction
and motor torque constants all differ from it, by amounts nobody has told you. The file has no friction at all.
There is no gravity compensation anywhere: if you do not hold the arm up, it falls.

Your job is to deliver `controller.py` in this directory. It will be given joint-space reference trajectories
it has never seen and must make the arm follow them. **Score: RMS joint tracking error in milliradians, averaged
over several hidden references. Lower is better.**

## The arm

You reach the real arm only through the Unix socket `/sim/sim.sock` (stream, one JSON object per line each way).
It runs in lockstep: it advances only when you step it, one frame of 1/30 s at a time, so you can take as long
as you like to think between frames. Every connection gets its own copy of the same arm, so you can run
experiments in parallel.

On connect you receive `{"type":"hello", ...}` with the joint limits, gain limits and torque limits. Then send:

- `{"type":"reset","q":[6]}` places the arm at rest at those joint angles (rad). Reply: an observation.
- `{"type":"step","q":[6],"qd":[6],"kp":[6],"kd":[6],"tau":[6],"n":1}` holds this drive command for `n` frames
  (1 to 300). Omitted `qd`, `kp`, `kd`, `tau` are zero. Reply: `{"type":"obs","t","q","qd","tau"}` for n = 1,
  or `{"type":"obs_batch","frames":[...]}` with one observation per frame.
- `{"type":"trial","name":"practice0"}` starts a scored practice run (see below).

An observation is taken at the end of each frame: `q` joint angles (rad), `qd` joint speeds (rad/s), `tau` the
torque each drive commanded (Nm). All three are noisy. A bad request gets `{"type":"error","msg":...}`.

**The drives.** Each joint has a motor drive that runs its own loop at 1500 Hz. During a frame it applies

    tau_motor = clip( kp*(q + qd*s - q_meas) + kd*(qd - qd_meas) + tau , -tau_max, +tau_max )

where `s` is the time since the frame began (0 to 1/30 s): the position setpoint moves at `qd` within the frame.
`kp` is capped at [120, 120, 120, 60, 15, 15], `kd` at [7.5, 7.5, 7.5, 2.25, 2.25, 2.25] (higher values are clipped), and `tau_max` is [28, 28, 28, 10, 10, 10] Nm.
The torque a motor actually delivers is not exactly `tau_motor`. Joint ranges are hard stops.

## What the controller must do

`controller.py` must define `control(robot, ref)`. `ref` is the whole reference, given up front: a dict of numpy
arrays `t` (N+1,), `q`, `qd`, `qdd` (N+1, 6), sampled at the frame times 0, 1/30, ..., 12 s. The arm starts at
rest at `ref["q"][0]`, already at the first sample. `robot.obs` is the latest observation (numpy arrays), and
`robot.step(q, qd=None, kp=None, kd=None, tau=None)` sends one frame's drive command and returns the next
observation. Call it once per frame; after N frames it raises an exception that you should let propagate.
If the controller stops early or crashes, the drives go limp for the rest of the reference.

The error is measured on the true joint angles at 1500 Hz against the smooth reference between samples too, so
what happens inside a frame counts. References are 12 s long and mix point-to-point moves, holds, very slow
creeps on a few joints and multi-frequency sweeps, at up to about 2 rad/s and 20 rad/s^2, staying well inside the
joint limits.

`controller.py` runs in its own process with Python 3, numpy, scipy and mujoco, and only `controller.py` is used
for scoring: copy anything you learn about the arm into it. It may load `tools/yam_nominal.xml`. It has no access
to the socket when scored and nothing else from this directory.

## Practice

`python tools/practice.py practice0` (also `practice1`, `practice2`) runs your `controller.py` on a practice
reference against the real arm exactly as scoring will, prints its error, and writes everything that happened to
`practice_runs/`. The hidden references are different trajectories of the same kind on this same arm.

You have 60 minutes of wall-clock time. Leave a working `controller.py` in place well before then.
